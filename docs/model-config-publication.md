# 后台模型配置发布

视觉识图和记忆抽取只读取已明确确认的 `nonebot/configs/models.yml`。旧安装首次使用时，停止所有配置编辑并自行核对现有文件完整性，取得该完整文件的 SHA-256，然后从 `nonebot` 目录运行：

```powershell
.\.venv\Scripts\python.exe -m model_publication --approve-existing configs\models.yml <已核对完整文件的SHA256>
```

此操作只写摘要标记，不重写现有配置，也不要求重新录入凭据。不能根据一次文件读取或固定等待证明其他程序已经写完：操作者必须确认没有并发写入且摘要属于完整文件；若误确认半写入内容，工具无法识别其意图。不要把配置、摘要标记或临时文件提交到仓库。

需要替换配置时，也可以先在仓库外准备并核对完整文件，计算其 SHA-256 后运行：

```powershell
.\.venv\Scripts\python.exe -m model_publication <仓库外的完整配置文件> <该文件的SHA256>
```

该命令以原子替换发布配置和摘要标记；两步之间或中断后后台请求会安全暂停。新文件使用发布进程的所有者和权限，请先确保机器人服务账号有读取权限。源文件必须与生效文件不同。

直接原地编辑生效文件、手动替换文件但不更新标记，或标记缺失，都会暂停后台模型请求。原地编辑完成且核对内容后，可以用上述 `--approve-existing` 重新确认，无需重复录入凭据。未发出模型请求的任务保留待处理并定时重试；已经开始请求后中断或失败的任务进入待人工判断状态（`review`），保留内容和上下文，只能由用户 `.记忆 重试` / `表情包学习重试` 明确重排，或显式删除。记忆与表情包队列的失败任务都不再按创建时间自动清理。

MuiceBot 1.1.5 的文件监视器不保证响应原子替换。发布后需使用其原生 `.model reload` 或按运维流程重启，待配置管理器完全加载后后台任务才会使用新版本。如果当前聊天条目已被删除，`.model reload` 可能失败；请显式加载存在的新条目或按运维流程重启。如果取消旧默认后没有任何条目设置 `default: true`，该版本的管理器可能保留旧默认；此时后台会暂停，需重启或明确设置有效默认并重新发布。

目前没有持久首选时，后台跟随 MuiceBot 当前生效的条目（`.model load <条目>` 选中的那个）；救援途中临时切到次选不会被当成主人的选择。若此刻没有可读的当前条目（例如 Muice 尚未启动），则使用发布配置里确认过的默认条目。首选失败且允许降级时，配置的次选会收到同一图片或记忆文本。正在处理的请求不会因后续发布撤回。当前仅支持 OpenAI 兼容 provider；向量模型不由聊天模型首选控制。此协议信任有权确认配置和写入标记的本地用户，不能防止同权限用户自行伪造标记。
